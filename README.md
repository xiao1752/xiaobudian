# CampusRun Sim —— 通用 GPS 路线模拟测试工具（原型）

这是一个通用的 GPS 路线模拟 / 测试工具原型，不是针对某一个 App
做的，也没有反编译、修改、绕过任何特定 App 的代码。
它可以按你在地图上选的路线，以你设定的配速和步频，持续地
向系统注入位置，让你在测试位置相关功能时不用真的出门跑一圈。

> **先说最重要的一句：没有任何方法能保证零封号风险。**
> 尤其是目标 App 如果做服务端校验（轨迹、配速、步频、步长、
> 速度变化、GPS 抖动、设备信息是否自洽），本地做得再像也可能
> 被判定为异常。本项目只能把本地轨迹做得更像真人，不能替你
> 绕过服务端的判断。用模拟位置提交正式的校园跑成绩，可能违反
> 学校或 App 的规则，有封号、成绩作废等风险，请自行权衡。

这个要求选出来的：

1. 手机已 root，刷入工具是 KernelSU（用户版本
   v3.3.1-24-g528bafc5），不是 Magisk。最终刷入步骤一律

2. 把本项目编出来的 APK 通过 KernelSU 模块（systemless，
   不直接改 system 分区）装成系统应用，见下面“安装”一节。
   模块目录是本项目里的 `kernelsu-module/`，不是
   `magisk-module/`（后者不存在）。
3. 用 App 内的前台服务跑路线：切到别的 App、灭屏时，前台
   服务 + 电池优化白名单 + 局部唤醒锁（只在跑步时持有，

4. 全程没有悬浮窗、没有传送、没有跳点；摇杆只在本 App 界面内（见下面摇杆模式一节），不做盖在小步点上的悬浮摇杆，
   速度只会平滑加速 / 减速，转弯会减速，到中途点会停留
   但仍持续发位置（和真人停下时接收机仍有信号一样）。

### 为什么不把别的方法当默认

- **普通模拟位置 App 模式（开发者选项里选模拟位置应用）：**
  风险最大。系统会留下一个可被查询的 mock 标记，很多 App
  一查就知道这是模拟位置。本项目不把它当默认，也不提供
  一键切换到这种模式的入口。
- **破解 / MOD APK：**
  不要用。来路不明的改包最容易夹带私货、偷账号，而且
  签名、版本和官方不一致本身就是异常信号。
- **用 Smali 反编译、修改目标 App：**
  不要做。这是直接改别人的 App，风险最高，也最容易在
  更新后失效、被判定为篡改。本项目完全不做这件事。
- **完美直线、无抖动、瞬间加速、瞬间传送的轨迹：**
  不要用。真人轨迹不会这样，服务端和本地检测都很容易
  从“太完美”看出来。本项目默认带小幅 GPS 抖动、加速
  减速和转弯减速，就是为了避开这一点。

旧的 Android 9 System Mode 不适用于 Android 14：
Android 10 之后相关内部接口已收紧，Android 14 更要走
上面这条系统应用 + KernelSU 路线，不要再按老教程走。

## 二、功能

- 地图选路线：地图上长按选起点、终点、中途点，OSRM 按
  道路重新算路线；也可以导入 GPX 轨迹；也可以用内置的
  示例校园环线（示例坐标，使用前请换成你自己的校园环线）。
- 校园环线：环线首尾相接，跑完一圈自动从起点连续再跑，
  不会跳回起点造成传送。环线必须在真实校园道路上，起点
  和终点要合理。
- 配速设置：按 min/km 或换算成 km/h、m/s，内部统一用
  m/s 推进。界面同时显示 min/km、km/h、m/s 三个数字。
- 步频设置：按步/分钟设置，App 自动算步长和每公里步数，
  三个数始终保持一致：
  - 步长（米）= 速度（米/分钟）÷ 步频（步/分钟）
  - 每公里步数 = 步频 × 配速（分钟/公里）
- 轨迹真实感：平滑加速 / 减速（最大约 1.0 m/s²）、转弯
  减速、中途点停留时仍发位置、小幅 GPS 抖动（默认 1.5 米）、
  每条位置带速度、方向、海拔、精度。
- 后台稳定：前台服务（Android 14 声明 location 类型）、
  电池优化白名单、灭屏不中断、切 App 不中断、暂停时
  原地发零速位置、继续时从原地接着跑，不传送。
- 开始 / 暂停 / 继续 / 停止齐全，没有跳点、没有悬浮窗；
  另有 App 内摇杆模式（见下面摇杆模式一节），由用户手动控制方向和速度。

## 三、配速 / 步频换算（已验算）

公式：
- 速度（m/s）= 1000 ÷（配速分钟 × 60）
- 速度（km/h）= 速度（m/s）× 3.6
- 步长（米）= 速度（米/分钟）÷ 步频（步/分钟）
- 每公里步数 = 步频 × 配速分钟

例子 1：配速 6:00/km，步频 180 步/分钟
- 速度 = 1000 ÷ 360 = 2.78 m/s = 10.00 km/h
- 步长 = 166.67 ÷ 180 = 0.93 米
- 每公里步数 = 180 × 6 = 1080 步，1000 ÷ 0.93 ≈ 1080，对得上。

例子 2：配速 7:30/km，步频 160 步/分钟
- 速度 = 1000 ÷ 450 = 2.22 m/s = 8.00 km/h
- 步长 = 133.33 ÷ 160 = 0.83 米
- 每公里步数 = 160 × 7.5 = 1200 步，1000 ÷ 0.83 ≈ 1200，对得上。

App 里对不合理的组合会直接拒绝并给出明确提示，不会
默默接受（以 `model/Validation.kt` 为准）：
直接拒绝的是配速超出官方 3:00–12:00/km、步频超出官方
50–300 步/分钟、以及步长超出 0.60–1.10 米的组合；
配速在 3:00–5:30/km、10:00–12:00/km，或步频超出
130–200 步/分钟时，只给警告、不直接拒绝。
默认配速 7:30/km、步频 160 步/分钟，就是一个普通学生
校园跑的合理组合，不是精英速度。

## 四、安全清单（开始前逐项核对）

1. 只用真实校园路线：路线在真实校园道路上，起点、终点、
   中途点都合理，不要从宿舍直接跳到操场、不要跨校区跳点。
2. 只用学生合理配速：建议 6:00–9:00/km，不要设精英速度，
   也不要设忽快忽慢的速度。
3. 配速、步频、步长三者一致：改一个，另两个自动对齐，
   不要出现“配速很快但步频很低”这种算不通的组合。
4. 保留小幅 GPS 抖动：不要关掉抖动做成完美直线。
5. 保留加速、减速和转弯减速：不要瞬间起步、瞬间停止、
   直角弯全速通过。
6. 中途点要停留：设了中途点就让它停一会儿再走，不要
   穿点而过。
7. 先短路线测试：第一次先跑几百米的短路线，检查有没有
   警告、异常提示、轨迹断点，确认没问题再跑完整路线。
8. 不要多账号、不要不切实际的日里程：一天跑几个账号、
   一天跑几十公里，都是服务端很容易看出来的异常。
9. 保持 App 和系统更新：旧版本、旧模块在新系统上更容易
   出兼容和检测问题。
10. 记住底线：没有任何方法能保证零封号，尤其有服务端
    校验时。出现警告就先停下来，不要硬跑完整场。

## 五、小步点 2.6.8 校园跑适配（陕西工业职业技术学院 渭城校区，男生）

规则来源：用户 2026-10-26 发的规则截图，发布者管理员，2026-09-06，标题“陕西工业职业技术学院 渭城校区跑步规则更改”。

- 已确认：用户手机已装小步点，版本 **2.6.8**，应用信息页权限含“附近的设备、身体活动和位置信息”，存储占用 1.10GB。用户是男生。
- **距离：单次最低 1.5km，每日计入成绩上限 3.0km（男女同值）。** 建议目标取中间值，不要卡在 1.5km 或 3km 的边界上跑，GPS 漂移很容易把边界成绩算成无效。初版建议目标 **2.0–2.5km**，跑完先核对小步点里显示的距离再调。
- **配速：3'00"–12'00" 分钟/公里。步频：50–300 步/分钟。** 这是官方硬性范围，代码里已按这个范围校验，超出直接拒绝。
- **官方范围宽，不等于随便填：** 例如配速 6:00/km 配步频 50 步/分钟，算出来步长 3.33 米，真人跑不出来，服务端一算就露馅。所以代码在官方范围之外又加了一层真实性校验：步长超出 0.60–1.10 米直接拒绝；配速偏快（<5:30/km）、偏慢（>10:00/km）、步频超出 130–200 步/分钟时给出警告。建议日常组合仍用 **6:00–9:00/km、160 步/分钟左右**。
- **有效时段：06:30:00–23:00:59。** 时段外不要开始，开始前先核对时间。
- **最大暂停时间：5 分钟。** 暂停尽量控制在 3 分钟以内，代码在超过 3 分钟时警告、超过 5 分钟时拒绝。
- **点位：已开启进阶段点位跑，点位是随机的。** 这是最关键的一点：点位不是固定坐标，不能提前把固定打卡点写死。正确做法是：先在小步点里开始跑步，看到它随机生成的当前阶段点位后，再把这个点位加到模拟路线里，按顺序经过、每个点停留片刻再走；进入下一阶段、出现新点位时，再加下一个点位。缺一个阶段点位、跳过点位、顺序错了，都可能导致该次成绩无效。
- **身体活动权限的提醒：** 小步点要了身体活动权限，说明它可能不只看 GPS，也看计步/活动数据。GPS 模拟出来的配速、步频、步长必须和它算出来的步数自洽，短路线测试时要同时看距离、配速、步频/步数三项，别只看距离对了就以为通过了。

## 六、摇杆模式（手动控制，针对随机阶段点位）

用户 2026-10-26 明确要求：尽量以摇杆形式自己控制着跑。
原因是小步点的阶段点位是随机的，自动路线没法提前写死，
手动摇杆可以一边看当前阶段点位、一边往那个方向跑。

- **摇杆位置：只在本 App 界面内。** 不做系统悬浮窗，不盖在
  小步点上面，这是安全和手动控制的折中：目标 App 那边看
  不到一个显眼的摇杆，但你自己能随时控制。
- **摇杆管什么：** 推的方向 = 前进方向，推的幅度 = 目标速度，
  推满 = 你设定的配速上限，默认不超过 6:00/km（2.78 m/s），
  不要推到 3:00/km 那种精英速度。摇杆回中 = 平滑减速到 0，
  仍持续发位置，这段时间算暂停，累计别超过 5 分钟，建议 3 分钟内。
- **摇杆不管什么：** 真正的速度、转向仍走平滑逻辑，加速度
  上限约 1.0 m/s²，转向每秒最多转 60°，不会瞬间满速、瞬间
  掉头、瞬间传送。步频也不由摇杆直接定：步长固定为你设定值
  （默认 0.83 米），步频 = 速度 ÷ 步长，随速度自动对齐。
- **随机点位的操作顺序：**
  1. 小步点里先开始跑，看到当前随机阶段点位；
  2. 切到本 App，用摇杆往点位方向推；
  3. 到点后切回小步点，确认该阶段已通过；
  4. 出现下一阶段点位，重复 2–3 步，直到跑满目标里程。
  也可以用分屏同时看两个 App，但不要让摇杆盖住小步点。
- **代码：** `simulation/JoystickController.kt`，每秒调用一次
  `update()`，输入摇杆 x、y（-1..1），输出平滑后的速度、
  方向、步频、配速。

4. 重启后确认 CampusRun Sim 出现在系统应用列表里，再
   打开它。不要再去开发者选项里选它当模拟位置应用——
   那正是要避开的 detectable 标记。
5. 到系统设置 > 电池里，把 CampusRun Sim 设为“不受限制”
   （电池优化白名单），否则灭屏、切后台时路线可能被杀掉。

## 十、使用流程（第一次就按这个顺序）

1. 地图：长按选起点、终点，必要时加中途点。
2. 路线：点“生成路线”，等 OSRM 算出道路路线；或者点
   “示例校园环线”先试手（记得把示例坐标换成你自己的）。
3. 配速：用滑杆选配速，同时看 km/h 和 m/s 是否合理。
4. 步频：用滑杆选步频，同时看步长和每公里步数是否合理。
5. 开始：点“开始”，切到别的 App 或灭屏，路线继续跑；
   想停就点“暂停”（原地发零速位置），想继续点“继续”，
   跑完点“停止”。
6. 报错时不要硬跑：
   - “请先在地图上长按选至少 2 个点”：就是还没选够点。
   - “路线计算失败”：检查网络，或换离道路更近的点。
   - “GPS 未开启”：先在系统设置里打开定位。
   - “配速 / 步频对不上”：按提示调配速或步频，不要强行
     用一个算不通的组合。
   - “GPX 文件解析失败”：确认是标准 GPX 轨迹文件。

## 十一、测试计划（先短后长）

1. 短路线测试（必须先做）：用示例环线或几百米的短路线，
   配速 7:30/km、步频 160 步/分钟，跑 2–3 分钟。检查：
   地图轨迹连续不断点、速度平滑上升不是瞬间满速、转弯
   有减速、暂停后原地不动、继续后从原地接着跑、有没有
   任何警告。
2. 完整路线测试（短路线没问题再做）：换成你自己的校园
   环线，跑完整的一圈，检查总距离、总时间、平均配速
   是否和设定一致，起点终点是否合理。
3. 后台测试：跑的时候切到别的 App、灭屏 1–2 分钟，再
   切回来，看路线有没有断、有没有跳点。
4. 只有上面三步都没警告、没断点、没跳点，再考虑正常使用。
   任何一步出现警告，先停下来排查，不要直接跑正式场次。

## 十二、代码结构（和 README 对得上）

- `app/src/main/java/com/campusrun/sim/MainActivity.kt`
  入口，申请定位和通知权限，显示主界面。
- `app/src/main/java/com/campusrun/sim/ui/MapScreen.kt`
  地图 + 第一步到第四步的操作界面，没有悬浮窗；摇杆模式的摇杆也在这个界面内。
- `app/src/main/java/com/campusrun/sim/ui/SimulationViewModel.kt`
  路线生成、配速 / 步频校验、开始 / 暂停 / 继续 / 停止、
  报错信息。
- `app/src/main/java/com/campusrun/sim/model/Models.kt`
  路线点、配置、配速换算、距离和方向计算。
- `app/src/main/java/com/campusrun/sim/model/Validation.kt`
  不合理配速 / 步频 / 步长的拒绝和警告规则。
- `app/src/main/java/com/campusrun/sim/route/OsrmApi.kt`
  OSRM 道路路线计算（GeoJSON，不用解 polyline）。
- `app/src/main/java/com/campusrun/sim/route/GpxParser.kt`
  GPX 轨迹点解析。
- `app/src/main/java/com/campusrun/sim/route/CampusLoop.kt`
  示例校园环线（示例坐标，使用前请替换）。
- `app/src/main/java/com/campusrun/sim/simulation/JoystickController.kt`
  摇杆模式：方向 + 目标速度输入，平滑速度、转向、步频输出。
- `app/src/main/java/com/campusrun/sim/simulation/SimulationEngine.kt`
  按弧长推进、加速减速、转弯减速、中途点停留、GPS 抖动。
- `app/src/main/java/com/campusrun/sim/location/MockLocationEngine.kt`
  通过系统测试位置提供者注入位置（主方法为系统应用安装）。
- `app/src/main/java/com/campusrun/sim/service/SimulationService.kt`
  前台服务、暂停 / 继续、灭屏唤醒锁、循环路线。
- `kernelsu-module/module.prop`
  KernelSU 模块信息，APK 放进对应目录后打包刷入。
